The crux: an AI scanner that finds where data goes missing

In climbing, the crux is the hardest move on a route, the one that decides whether you top out. Mine right now is my newest project as a staff engineer: agents that read all of Aledade's ingestion streams (MSSP data, commercial payer data, pharmacy claims, SIU provider claims, ADT records, patient matching and more), prove where values can be lost, measure what each loss costs downstream, and open the pull requests that close it.

  1. 1

    Flag

    Haiku + Opus

    Four-lens workflow reviews read every ingestion pipeline and flag each place a record could drop.

  2. 2

    Prove it upstream

    Opus, evidence agent

    Walks upstream from each flag: reads the code, queries the tables, reads the raw files, until the gap is proven or ruled out.

  3. 3

    Measure downstream

    Opus, impact agent

    Follows each proven gap into what it feeds: doctor recommendations in the practice web app, finance and SEC reporting, and the practice transformation specialists who help practices. Counts the values at stake and draws the Sankey below.

  4. 4

    Fix

    Pull request

    The biggest gaps come back as pull requests. Once they merge, the scanner reruns until nothing is lost.

The hard part is proof

Flagging a possible gap is easy. Proving it is not, and the kind of proof a gap needs decides how the upstream agent works.

  • Proven in code

    The transform drops rows on its face, like a schema change it never handles. The agent cites the exact lines.

  • Needs a table query

    The code looks right but the counts disagree. The agent queries source and target tables and shows the difference.

  • Needs a file read

    The loss happens before any table, in a malformed or late file. The agent reads the raw files to show which records never arrived.
